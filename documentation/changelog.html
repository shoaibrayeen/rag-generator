Changelog

All notable changes to RAG Generator. Versions follow app/main.py's FastAPI version.

0.5.0 2026-09-06

Added Pagination for the job and document listings.

  • Changed GET /api/jobs and GET /api/documents return an envelope {items, page, size, total, pages, has_next, has_prev}; page is 0-based (default 0), size defaults to 5 (LIST_PAGE_SIZE, max LIST_MAX_PAGE_SIZE).
  • Added UI prev/next pagers under the Jobs and Documents panels; CLI --page / --size on rag jobs and rag status.
  • Docs enhancements.md lists future improvements; README, architecture and plan change log updated.

0.4.0 2026-09-06

Added Jobs are first-class: one upload request = one job that owns its documents; questions can be scoped to documents and/or jobs; answers carry validated citations.

  • Changed POST /api/documents now returns the job (job_id, derived status QUEUED / PROCESSING / COMPLETED / FAILED, reason, per-status counts, documents). Document records keep the parent job_id.
  • Added GET /api/jobs listing (JOB ID · FILES · STATUS · REASON) and GET /api/documents?job_id= to see one job's documents. UI: Jobs panel; clicking a job filters the Documents panel.
  • Added Scoped asking: POST /api/ask accepts doc_ids and job_ids; both retrievers (Chroma where filter, BM25 candidate filter) honour the scope. Validation: 404 unknown id, 409 not COMPLETED, 400 mixed collections. UI: tick jobs/documents; CLI: rag ask --doc … --job ….
  • Added Answer payload: citations (sources actually cited, first-use order), unresolved_citations (bogus [n] markers removed from the text), scope. UI shows a Citations list under the answer and a "cited" badge on sources.
  • Added CLI rag jobs, rag job <id> (job + documents), rag status --job.
  • Changed Storage is now three named stores: jobs and documents (JSON registries) and one ChromaDB collection document_chunks whose metadata carries collection, doc_id and job_id. Document sets, documents and jobs are metadata filters instead of separate Chroma collections; GET /api/chunks accepts doc_id / job_id.
  • Fixed Collection names are validated with ChromaDB's rule (3-63 chars) instead of accepting 2-char names Chroma rejects.
  • Docs README, architecture, flow walkthrough updated; approved plan and its mid-session changes committed under plans/.

0.3.0 2026-09-06

Changed Extraction is now explicitly two-tier: primary extractors first, Tesseract OCR strictly as the fallback.

  • Changed PyMuPDF replaces pypdf as the primary PDF extractor and also renders pages for OCR (pypdfium2 removed).
  • Added Fallback tier in app/ingest/extractors.py (FALLBACKS registry): OCR of all PDF pages, OCR of images embedded in DOCX, stdlib tag-stripping for HTML. Runs only when the primary extractor raises or yields no text.
  • Added ExtractionError with user-facing reasons; a scanned file on a host without Tesseract now fails with "Tesseract OCR is not installed…" instead of a generic message, and a corrupt PDF reports "Could not read this pdf".
  • Added Multi-encoding decoding for TXT/MD/CSV (utf-8, utf-16, cp1252, latin-1).
  • Added scripts/export_transcript.py (Markdown transcript from the Claude Code session log), scripts/sync_rules.py (CLAUDE.md → Cursor / Codex rule copies), scripts/build_docs.py (HTML twins for Markdown docs).
  • Docs Documentation moved to documentation/; README, architecture and flow updated for the two-tier extraction; APP_PORT documented.

0.2.0 2026-09-06

Changed Upload is now an explicit asynchronous job flow with a fixed status vocabulary.

  • Added Per-file job_id in the upload response and GET /api/jobs/{job_id} to poll it.
  • Added Statuses QUEUED · DUPLICATE · PROCESSING · COMPLETED · FAILED · EMPTY_FILE · EXTRACTION_NOT_SUPPORTED · UPLOAD_FAILED, each with a human-readable reason; PROCESSING exposes a stage.
  • Added SHA-256 duplicate detection per collection. Duplicates are recorded but never processed and link to the original document.
  • Changed Rejected uploads (unsupported extension, empty file, oversize, storage error) now become listed records instead of a 400 error.
  • Changed UI listing shows Doc ID · Name · Status · Reason; GET /api/documents accepts a status filter.
  • Added rag job <id> CLI command; rag status prints the same four columns.
  • Docs architecture.md, this changelog, the interactive flow walkthrough, CLAUDE.md (documentation-update rule) and memory.md (project memory).

0.1.0 2026-09-06

Added Initial release.

  • FastAPI REST API + single-page UI (upload, status, ask, sources) + rag CLI.
  • Extractors for PDF, DOCX, HTML, TXT, MD, CSV with page metadata; PNG/JPG/TIFF and scanned PDF pages via Tesseract OCR fallback.
  • Overlapping, metadata-tagged chunking; fastembed embeddings; ChromaDB (embedded, persistent).
  • Hybrid retrieval: dense top-k + rank-bm25 top-k fused with Reciprocal Rank Fusion.
  • OpenAI-compatible LLM client configured only through .env; grounded prompt with [n] citations and an explicit "not found" fallback.
  • Evaluation script with Claude as judge (evaluation/run_eval.py) and dataset generator.
  • Dockerfile (Tesseract + pre-downloaded embedding model) and docker-compose with a data volume.
  • Offline mock LLM (scripts/mock_llm.py) and sample corpus (samples/).
